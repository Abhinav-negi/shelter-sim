### [ ] T-78 — Exclude test files from `apps/web/tsconfig.json` so `npm run build` survives `app/api/` deletion

**Area:** A — Foundation & contracts · **Status:** DONE · **Est:** 30 min
**Depends on:** T-03 · **Conflicts with:** T-36 (tsconfig.json — check it is not claimed)

**Why this exists.** T-66 found a ledger defect (reported honestly, not routed around): T-66
acceptance test 5 requires that `npm run build --workspace apps/web` still succeeds and produces
a full result when `apps/web/app/api/` is deleted. It does **not** succeed today.

Root cause: `apps/web/tsconfig.json`'s `include` list (`"**/*.ts"`, `"**/*.tsx"`) type-checks
every `.ts` file in the project, including `components/inputs/inputs.test.ts`. That file contains
a live `await import('../../app/api/materials/route')` (T-44 test 12 — a legitimate test
exercising the DB-off path). When `app/api/` is deleted, `tsc` cannot resolve the import and
exits 1, causing `next build` (which runs `tsc`) to fail.

The fix is to exclude test files from `apps/web/tsconfig.json`'s `include` so that `next build`
and `npx tsc --noEmit -p apps/web/tsconfig.json` do not attempt to type-check them. Vitest
uses esbuild (not tsc) to run tests, so excluding test files from tsconfig does **not** affect
test execution — the existing comment in `tsconfig.json` at line 20–27 already documents this
exact reasoning.

**The condition on T-44 test 12 must NOT be weakened.** The test exercises a real behaviour
(DB-off path) and must continue to pass in vitest. Only the `tsconfig.json` `include`/`exclude`
is changed.
