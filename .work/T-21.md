## Deviations and notes for downstream tasks
- index.ts's coefficient hook does not call `effectiveAch()` when `envelopeAreaM2 <= 0` (the
  fully-adiabatic capacitance fixture, Test 4 / `adiabaticBox()`, legitimately has no exterior
  envelope and no windows) -- it passes the achSchedule through unchanged instead, relying on
  `infiltration()`'s own independent ACH_MIN enforcement downstream. Without this guard the
  pre-existing Test 4 hard-gate suite (3 tests) went red. `effectiveAch()` itself is unchanged from
  the literal PROMPT contract and still throws unconditionally on `envelopeAreaM2 <= 0` when asked.
  ACH_MIN is never weakened by this for any real building (which always has positive envelope area).
- T-56 (optimiser's independent floor check) and T-51 (KPI panel rendering the new warning) should
  both be unaffected: the warning text contains the words "carbon monoxide" and "ventilation" as
  required, and the floor logic is unchanged for any request with a positive envelope area.
- **Finding for whoever revisits AUDIT F-6 / K-05:** the coupling as specified (envelope area
  inclusive of the swept glazing in the denominator) is mathematically concave in glazing area, and a
  concave loss term added to an approximately-linear gain/loss trade-off can only ever produce an
  interior MAXIMUM or a monotonic curve, never the interior MINIMUM the K-05 diagnostic wants. Two
  possible fixes for a future task (not made here -- both touch files this task may not, or the
  frozen constant this task may not retune): (a) normalise the coupling by the FIXED opaque envelope
  area only (excluding the glazing being swept), which makes the coupling term linear instead of
  concave, or (b) raise `ACH_PER_GLAZING_FRACTION` well above 1.2 so the (still concave) penalty is
  large enough to dominate at the swept fractions. Either requires re-deriving/re-justifying the
  calibration comment, which is exactly the kind of change this task's own PROMPT reserves for "a
  measured blower-door figure."

## Blocked by
(only when status is BLOCKED)
Acceptance test 7 (LOG.md T-21) cannot be satisfied: the sweep of south glazing 0%-50% on
shelterA_stone400 never produces an interior optimum in auxEnergyKWhPerDay, across 15+ tried
configurations (glazing type, shading, solar strength, setpoint, building proportion). This is an
algebraic consequence of the PROMPT's own coupling formula (concave in glazing area) combined with
the approximately-linear solar-gain/window-conduction trade-off, not an implementation bug -- see the
LOG.md Evidence block for the full derivation and data. Acceptance tests 1-6 and 8-11 all pass with
real measured numbers.
