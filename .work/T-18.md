## Deviations and notes for downstream tasks

- **SunPosition field names**: the PROMPT's pseudocode referenced `sun.altitudeDeg`,
  `sun.azimuthDeg`, `sun.isUp`. The actual `SunPosition` on disk (solar/geometry.ts, not edited)
  has `altitude` / `azimuth` (already degrees) and no `isUp` field. shading.ts uses `sun.altitude`,
  `sun.azimuth`, and `sun.altitude > 0` for "is up" -- documented in a header comment in the file.
- **Horizon guard in `overhangSunlitFraction`**: uses `sun.altitude < 0` (strict), not `<= 0`, to
  return "no beam" -- at exactly 0 deg the geometric formula already evaluates to a fully sunlit
  window, so a `<=` cutoff caused a spurious discontinuity right at the horizon that failed the
  continuity acceptance test (#8). Documented with an inline comment at the guard.
- **Ready to wire in**: `horizonBlockFactor` and `overhangSunlitFraction` are pure, side-effect-free
  functions ready to be called from the forcing hook that computes beam irradiance per surface
  (owned by T-16's file set / whichever task next touches `index.ts`'s forcing vector assembly).
  Per the PROMPT, this task deliberately does NOT wire them into `index.ts`.
- Not implemented, per the binding cut list (global rule 12) and the PROMPT: ray tracing,
  inter-building shading, view factors, DEM download.
- Shading is applied to the BEAM component only -- see the `// SIMPLIFICATION:` comment in
  shading.ts for the ceiling (a blocked horizon/deep overhang also blocks part of the sky dome,
  which is not modelled) and upgrade path (sky-dome view-factor reduction on the diffuse term).
  This must reach the limitations list (T-64) and EQUATIONS.md.
