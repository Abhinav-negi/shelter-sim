# A1 — "Run on ANSYS" placeholder
Status: IN-PROGRESS      Depends on: –

## Goal
A user-approved placeholder that makes ANSYS feel like a real, long-running feature. Studio header gets "Run on ANSYS"
next to "Save run" → confirm dialog ("ANSYS simulations can take up to 7–8 hours to complete. Do you want to
continue?") → the design shows "ANSYS running · H:MM:SS", ticking forever until Cancel, in the Dashboard row and the
Studio header. Persisted server-side as one timestamp, so it survives logout/login/devices. No "coming soon" wording,
no fake results.

## Conditions
1. API.md §8 updated first: `DesignSummary.ansysStartedAt: string | null`; `POST /api/designs/:id/ansys` → 200
   DesignSummary (idempotent: keeps existing start); `DELETE /api/designs/:id/ansys` → 200 DesignSummary (null).
2. Model `ansysStartedAt: Date|null` default null; start/cancel use `getOwnedDesignDoc` (other user → 404) and
   `save({ timestamps: false })`; PUT leaves the field unchanged.
3. mongo.test.ts covers: start sets field · second start same timestamp · cancel → null · other user 404 · PUT keeps it.
4. `AnsysTimer` ({startedAt, onCancel, cancelling?}): 1 s interval, H:MM:SS from `Date.now() - startedAt`, hours unbounded,
   `font-mono tabular-nums`, ghost Cancel.
5. Studio: secondary "Run on ANSYS" button; native `<dialog>` + `showModal()` confirm (Cancel/Continue); Continue saves
   design first if unsaved/dirty (same as `handleSaveRun`), then startAnsys; while running the timer replaces the button;
   errors use the existing error-strip pattern. Loading-state header also shows a disabled "Run on ANSYS".
6. Dashboard `DesignRow`: timer + Cancel when `ansysStartedAt` set; cancel updates that row.
7. `npm test -w @shelter/studio-server`, `npm test -w @shelter/studio`, `npm run build -w @shelter/studio` green;
   frozen guard empty.

Gotchas:
- Mongoose's `HydratedDocument.save({ timestamps: false })` (used by both `startAnsys`/`cancelAnsys`
  in `service.ts`) is the mechanism condition 2 asks for — it's a per-call option, not a schema
  setting, so `updatedAt` genuinely doesn't move on a start/cancel.
- `AnsysTimer` takes `startedAt` as the ISO string straight from `DesignSummary.ansysStartedAt` and
  converts with `new Date(startedAt).getTime()` internally, so both Studio and Dashboard pass the
  server value through unmodified.
- No prior `<dialog>`/`showModal()` usage existed anywhere in `apps/studio` to match against; styled
  it with the existing tokens (`bg-paper`, `border-hairline`, `backdrop:bg-ink/40`) to match the
  rest of the app's instrument-panel look rather than a generic modal.
- Confirm-dialog copy is exactly the wording condition 1/the Goal section specifies ("ANSYS
  simulations can take up to 7–8 hours to complete. Do you want to continue?"); no "coming soon"/
  "placeholder"/"demo" wording appears anywhere in user-visible text (only in code comments, which
  the task allows).
- Dashboard's `handleCancelAnsys` merges only `ansysStartedAt` into the row's existing `summary`
  (rather than replacing the whole object with the cancel response) so a concurrent dawn-temp update
  to the same row can't be clobbered by a stale `design`/`name` from the ansys response.
