## Goal
The core design experience: controls → store → 3D model, with a debounced preview simulation and results that
explain the outcome.

## Conditions
1. Control groups: Environment (preset/custom location via search, date), Geometry, Materials (material + thickness
   per surface), Openings (WWR per facade, glazing, shutters), Orientation (dial), Advanced (occupancy). Ranges come
   from `/api/options`.
2. Each change updates the 3D model immediately and triggers a preview 400 ms after the last change. Stale responses
   are discarded (AbortController).
3. The status shows the real stages, not timers. Errors say what happened and offer a retry. Custom-location weather
   provenance notes are visible.
4. Results: indoor vs outdoor chart (°C, thermal colours), heat-flow pathway breakdown (daily kWh), the engine KPIs
   listed in PLAN.md, and "What happened / Why" from the ported explain logic. No invented metrics.
5. Save design / Save run (P2 routes) persist the design and the run.
6. Screenshots at 1440 and 390 px, light and dark. No console errors.

## Rules
Do not expose every engine variable. Advanced stays collapsed. Units are always shown in mono.

**Two real bugs found and fixed during live QA (both within/adjacent to allowed scope, not viewer/store/server):**

1. **Save run was broken (500, condition 5).** `apps/studio/src/api/client.ts`'s `request()` unconditionally sent
   `Content-Type: application/json`, even for `POST /api/designs/:id/simulations` (API.md §9: no request body).
   Fastify's default JSON body parser rejects a `Content-Type: application/json` request with an empty body
   (`FST_ERR_CTP_EMPTY_JSON_BODY` → 500 `INTERNAL_ERROR`) — confirmed via the scratch server's `console.error` stack
   trace (logger is off, so this only surfaces server-side; the client just sees a generic 500). `client.ts` isn't
   in F3's "may touch" list, but this is exactly the "one-line wiring fix elsewhere in apps/studio/src" the brief
   allows for — the bug is entirely in this shared fetch wrapper, not in a frozen file, and condition 5 cannot pass
   without it. Fix: only set the JSON content-type header when `init.body !== undefined`. This changed the exact
   `fetch` call shape for every body-less request (GET/DELETE/logout/runSimulation), so the 6 pre-existing api-wrapper
   test files (`auth.test.ts`, `designs.test.ts`, `health.test.ts`, `locations.test.ts`, `options.test.ts`) had their
   `toHaveBeenCalledWith(...)` assertions updated to match — they were asserting the buggy behaviour, not a real
   contract; nothing about *what* is sent (method/URL/body) changed, only that the header is now sent conditionally.
   `previewSimulation`/`createDesign`/`updateDesign`/login/register (all of which do send a body) are unaffected.
2. **Heat-flow chart: value label overlapping the row's category label (condition 6 visual QA, both light/dark,
   1440 px).** `HeatFlowChart.tsx` used recharts' `LabelList position="right"`, which anchors the label beyond the
   bar's tip *in the value's own direction* — for a large-magnitude **negative** bar (e.g. "Radiated to night sky"
   at −138.6 kWh) that direction is further left, past the tip, landing the number directly on top of the row's own
   axis label text (visually merged, e.g. "Radiated to nigh138.6 kWh"). Root cause + fix: an SVG rect's `x`/`width`
   are always non-negative (`x` = the smaller of the two scaled endpoints), so `x + width` is always the bar's true
   screen-right edge — the tip for a positive bar, the zero line for a negative one — and is never further left than
   the plot's own zero reference. Replaced the built-in `position="right"` with a small custom `content` renderer
   (`ValueLabel`) that anchors there directly. Verified by screenshot: all labels (positive and negative, including
   the two large negative ones that previously collided) now sit cleanly to the right of their bars with no overlap,
   at both 1440 and 390 px, light and dark.
3. **390 px header overflow (condition 6).** The Studio header row (name input + save-state label + 2 buttons) was
   a single non-wrapping flex row; at 390 px the two buttons ("Save design"/"Save run") and the status label left
   almost no room for the name input, truncating "Untitled shelter" to ~5 visible characters. Fixed in
   `routes/Studio.tsx`: the row is now `flex-wrap`, and the name input is `basis-full` below the `sm` breakpoint
   (own line) and `flex-1` at `sm:` and up (original single-line layout, unchanged on desktop). Verified: 390 px now
   shows the full name on its own line with the status/buttons wrapping below it; 1440 px is pixel-identical to
   before (single line, unchanged).
