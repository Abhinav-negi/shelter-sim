## Key finding that makes shapes possible without the engine
The engine is surface-based. `Surface{type, area, tilt, azimuth, construction, boundary…}` is defined in
`packages/engine/src/types.ts:67`. The engine derives floor area from floor surfaces
(`engine/src/solve/assemble.ts:143`). The "box" exists only in `setSize` in
`apps/studio-server/src/design/assemble.ts:323`, which is not frozen. So any shape can be sent as a list of facet
surfaces. Only the studio-server's assemble and the client viewer need to learn about shapes.

### G2 — shape contract (API.md first)
- `ShelterDesign` gains **optional** fields with defaults, so saved designs and frozen run snapshots stay valid:
  ```ts
  shape?: 'box' | 'cylinder' | 'dome'   // default 'box'
  storeys?: 1 | 2                       // default 1; heightM = height per storey; dome ⇒ must be 1
  ```
  - Cylinder: `lengthM` = diameter (`widthM` ignored).
  - Dome: hemisphere, `lengthM` = diameter (`widthM` and `heightM` ignored).
  - Update the validation schema in `app.ts` and add them to `/api/options` `defaults`. `ranges` needs no change.
- `assemble.ts` gets a new `setShape(request, design)`, which replaces `setSize` for non-box shapes. **The box path
  stays byte-identical** (the existing `parity.test.ts` must stay green). It takes the preset's S wall, roof and
  floor as templates (construction, absorptivity, emissivity, boundary) and generates facets:
  - **Cylinder:** N=12 wall facets at azimuth k·30°, each with area πD·h/12 (h = heightM·storeys). The roof and
    floor are each πr². Volume is πr²h.
  - **Dome:** 3 elevation bands × 12 sectors. Each band's area uses the spherical-zone formula 2πr·Δz/12. Band
    tilt is 90° minus the mid-elevation. Facets with tilt ≥ 60° are `wall`s (wall construction, can hold windows);
    the rest are `roof`s. The floor is πr² and the volume is ⅔πr³.
  - **Two storeys (box/cylinder):** wall areas and volume ×2, roof and floor footprint unchanged. The intermediate
    slab is added as one `rock` `StorageElement`. Its mass is footprint × slab thickness × density, using the
    preset floor material. Its conductance is 2 × footprint × ~8 W/m²K. The implementer must check the engine's
    storage validation. API.md must state that this is a single-zone approximation.
- **WWR semantics:** generalise `wallForOrientation` into `wallsInQuadrant(o)`, the walls whose azimuth is within
  ±45° of the cardinal direction (ties at ±45° go to S/N). The quadrant's WWR is spread over those walls in
  proportion to area. For a box each quadrant has exactly one wall, so its behaviour is unchanged.
- Tests (vitest, pure):
  - Area and volume sums per shape match the closed-form values within 1e-9.
  - Every generated request passes the engine's `validate`.
  - Preview returns finite KPIs for cylinder, dome and box-2-storey.
  - A cylinder with the same floor area and height as a box has less wall area.
  - The box parity test is unchanged.
  - A mongo test shows a saved design without `shape` loads as a box.

### G3 — shapes in viewer + controls
- `geometry.ts` returns a shape-tagged `SceneGeometry` that mirrors the server's facets (so what you see is what is
  simulated):
  - A box is a 4-facet polygon.
  - A cylinder is a 12-facet polygon. The mitre angle is generalised from 45° to 180°/N, so the extruded-wall code
    in `Building.tsx` (`mitreWallEnds`) is reused for each facet.
  - A dome is a flat-shaded hemisphere built from the same bands.
  - Windows sit on the facet(s) nearest each cardinal direction.
  - Two storeys means stacked walls, a thin intermediate slab and one window row per storey.
- `GeometrySection.tsx` adds:
  - a shape `Segmented` (Box / Cylinder / Dome)
  - a storeys `Segmented` (1 / 2, disabled for dome, with a hint saying why)
  - a relabelled "Diameter" field for cylinder and dome; width is hidden for those, and height is hidden for dome
  - a quiet note "Two storeys are simulated as one connected air volume".
- Store: add setters. Normalise a missing `shape`/`storeys` on load.
- Tests extend `geometry.test.ts` and `Building.test.ts` (facet count, the mitre angle closes the ring, dome band
  areas). Screenshots of each shape at 1440/390 × light/dark.

### G4 — select to edit
- Store: add a separate UI slice (not persisted, not in `ShelterDesign`):
  `hoveredPart`, `selectedPart: PartId | null`, where
  `PartId = 'wall:S'|'wall:E'|…|'window:S'|…|'roof'|'floor'`.
- Viewer:
  - Meshes carry the `PartId`. R3F `onPointerOver`/`onPointerOut`/`onClick` call `stopPropagation`.
  - Hover shows an accent outline or emissive tint. Selection gets a stronger tint.
  - Clicking empty space or pressing Esc clears the selection.
  - A cylinder facet maps to its quadrant's `wall:<o>`.
- Controls:
  - `Section` gets an `id` and a controlled `open`.
  - `FieldRow` gets an optional `part` prop.
  - On `selectedPart`: open the section, `scrollIntoView({block:'nearest'})` and briefly highlight the row.
  - The reverse direction: focusing or hovering a field with a `part` sets `hoveredPart`/`selectedPart`, so the
    model lights up.
  - Mapping: `window:o` → Openings / "o window %"; `wall:*` → Materials / walls; `roof` → Materials / roof;
    `floor` → Materials / floor.
- `PartPopover.tsx`: a drei `<Html>` anchored at the selected part. It shows the part name plus 1–2 `NumberInput`s
  from G1 (window %, construction thickness), writes through the same store setters and has a close button.
- Keep `frameloop="demand"`. State changes re-render, which invalidates the frame.
- Check the E2E path: clicking the south window opens Openings and focuses the south window field.
