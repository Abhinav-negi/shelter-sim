ShelterSim, explained from the ground up

The big picture

ShelterSim is one repository (an npm workspaces monorepo) with five app folders and three shared libraries. The product being built is Studio: a React + Vite client (apps/studio) and a Fastify server (apps/studio-server). Two earlier generations are kept frozen: the classic form-based app (apps/client + apps/server), and the first prototype, a Next.js full-stack app (apps/web). Studio is not Next.js: it is a single-page app whose entry is apps/studio/index.html. All of them run the same physics engine.

Technology used, and why

Everything is TypeScript. Versions come from each package.json.

How the codebase is divided

Each box is a workspace (a folder with its own package.json). Studio code is what you'll change. Packages are shared and frozen. The original app is frozen history.

How login works

  1. Register / login (auth/routes.ts): the password is hashed with scrypt and a 16-byte salt (auth/password.ts) and checked with timingSafeEqual. A login with an unknown email still hashes against a dummy hash, so response timing can't reveal which accounts exist.
  2. Cookie: the server signs {sub: userId} with JWT_SECRET and sets it as the cookie token. It lasts 7 days and is httpOnly and sameSite=lax. It is secure only when NODE_ENV=production.
  3. Guard: auth/authenticate.ts runs as a preHandler on every designs and simulations route and on /auth/me. A bad or missing cookie returns 401. A resource you don't own returns 404, so its existence isn't revealed.
  4. Client: RequireAuth calls /auth/me. On 401 or a network error it redirects to /login. Logout clears the cookie.

The engine and the data

  1. Load the base request from the preset (resolvePreset).
  2. Set weather and site from design.location: bundled TMY for a preset site, weatherFor() for a custom one (422 if it's missing).
  3. Set building.azimuth = azimuthDeg. The engine applies the rotation.
  4. Build the shape: setSize (box), cylinderGeometry or domeGeometry, then addIntermediateSlab if there are 2 storeys.
  5. Apply wall, roof and floor construction overrides, only where they aren't null.
  6. Set the window-to-wall ratio per quadrant. A wall belongs to the quadrant within ±45° of its facing; ties go to S or N.
  7. Apply the glazing type and night shutters (R 0.4, 20:00–06:00).
  8. Apply the occupancy preset (OCCUPANCY_PRESETS).
  9. Set the options: 1 simulated day and skyModel: 'isotropic'. This setting is load-bearing; the other sky model diverges on these presets.
